## 📝 使用说明

### 1. Bug报告编写流程

1. **发现Bug**：立即记录，不要依赖记忆
2. **确认级别**：根据影响范围判断严重级别
3. **编写报告**：按模板填写完整信息
4. **添加附件**：截图、日志等证据
5. **提交报告**：通知相关负责人

### 2. Bug严重级别定义

| 级别 | 定义 | 示例 | 优先级 |
|------|------|------|--------|
| **P0 阻塞性** | 核心功能完全无法使用 | 应用无法启动、无法问答 | 最高 |
| **P1 严重** | 重要功能受影响，但可绕过 | 部分问题无法回答、页面崩溃 | 高 |
| **P2 一般** | 功能可用，但有明显问题 | UI错位、动画卡顿 | 中 |
| **P3 轻微** | 小瑕疵，不影响使用 | 文案错误、颜色不协调 | 低 |

### 3. Bug命名规范

格式：`[功能模块] [问题类型] [简短描述]`

示例：
- `问答系统 无法显示回答内容`
- `路线规划 生成按钮无响应`
- `数字人状态 状态切换不正确`
- `前端UI 地图路径动画卡顿`

### 4. 快速模板（复制使用）

